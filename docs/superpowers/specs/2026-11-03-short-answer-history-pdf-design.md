# 주관식(단답형) · 시험 점수 이력 · PDF 가져오기 설계

작성: 2026-11-03 · 관련 이슈: #27(주관식), #32(점수 이력), #25(기출 출처) · 기준 설계: `2026-11-03-todaycertificate-design.md`

## 1. 왜 하는가

- 정보처리기사는 필기 다음에 실기가 있다. 실기는 단답형이라 지금 앱(객관식만)으로는 연습할 수 없다.
- 시험 모드 결과는 이미 저장되지만, 사용자는 "점수가 오르고 있는지"를 볼 곳이 없다.
- 기출을 PDF로 구한다. 지금은 손으로 CSV를 만들어야 해서 회차 하나 올리는 데 시간이 오래 걸린다.

## 2. 목표 / 하지 않는 것

목표
- 단답형 문제를 공부 모드·시험 모드·오답노트·별표에서 객관식과 똑같이 쓴다.
- 자격증별 시험 점수 이력(목록 + 꺾은선 그래프)을 보여준다.
- 운영자가 PDF를 올리면 미리보기 표로 바꿔 주고, 고친 뒤 저장한다.

하지 않는 것
- 서술형·부분 점수·사람이 하는 채점
- 그림이 있는 문제(#28), 주관식 PDF 변환(샘플이 없음), 스캔 PDF(OCR)
- 공공데이터 시험일정 API(#30은 별도)

실패로 볼 것 (돌아가도 안 되는 것)
- 실제 기출(시나공, comcbt 자료)이 레포나 배포 DB에 들어가는 것. 두 출처 모두 DB 저장·재배포를 금지한다.
- PDF 변환 결과가 검토 없이 바로 저장되는 것
- 기존 객관식 기능(채점, 정답률, 과락 리포트)이 깨지는 것

## 3. 사용자와 정한 것

- 주관식 = 단답형. 기본은 대소문자 구분 없음.
- 실기는 필기와 **별도 자격증 항목**으로 만든다 ("정보처리기사 실기": 과목 1개, 과락 0, 합격 평균 60). 채점 규칙(과락·평균)은 지금 것을 그대로 쓴다.
- PDF는 미리보기 → 수정 → 기존 CSV 검증·저장 흐름.
- 데모(레포, 배포 DB)에는 직접 만든 예시 문제와 예시 PDF만 넣는다. 실제 기출은 로컬에서만 쓴다.
- 순서: 주관식 → 점수 이력 → PDF 가져오기.

## 4. 주관식(단답형)

데이터 (`V2__short_answer.sql`)
- `question.type` VARCHAR(20) NOT NULL DEFAULT 'MULTIPLE_CHOICE' (`MULTIPLE_CHOICE` | `SHORT_ANSWER`)
- `question.choice1~4`, `answer_no`: 주관식이면 NULL. CHECK로 "객관식이면 보기 4개·정답번호 1~4 필수, 주관식이면 answer_text 필수"를 건다.
- `question.answer_text` TEXT: 허용 답을 `|`로 구분 (`DDL|데이터 정의어`)
- `question.exact_match` BOOLEAN NOT NULL DEFAULT false
- `solve_record.selected_no` NULL 허용, `solve_record.answer_text` TEXT 추가 (둘 중 하나만 채움)

채점 (`Question.isCorrect`)
- 기본: 양쪽 앞뒤 공백 제거, 연속 공백은 하나로, 대소문자 무시 후 허용 답 중 하나와 같으면 정답
- `exact_match = true`: 앞뒤 공백만 제거하고 글자 그대로 비교 (코드 출력값 문제)
- 빈 답은 오답. 부분 점수 없음.
- 순수 함수로 두고 단위 테스트로 규칙을 고정한다.

API
- 풀이 요청: `{ selectedNo }` 또는 `{ answerText }`. 문제 유형과 안 맞으면 400.
- 시험 제출 답안도 같은 형태. 결과의 정답 표시는 객관식은 `answerNo`, 주관식은 `answerText`.
- 문제 조회 응답에 `type` 추가. 주관식은 `choices`가 빈 배열.
- 정답률(#23)의 "많이 고른 오답"은 객관식만 계산한다. 주관식은 정답률만.

CSV
- 맨 끝에 `유형` 칸을 선택으로 추가. 없거나 비면 객관식 (지금 CSV 그대로 동작).
- 주관식: 보기 칸 비움, `정답번호` 칸에 답 글자, `유형`에 `주관식` 또는 `주관식-정확히`.

화면
- 보기 대신 입력칸 + "확인"(공부) / 입력만(시험). 웹은 Enter로 확인.
- 결과·오답노트에 "내 답 / 정답(허용 답 모두)" 표시.

## 5. 시험 점수 이력

- API: `GET /api/me/attempts?certificateId=` → 제출된 시험만, 오래된 순. 항목: `attemptId, examYear, examRound, submittedAt, averageScore, passed`
- 화면: "내 학습"에 "점수 이력" 칸 → 자격증 고르기 → 꺾은선 그래프(합격선 60 표시) + 목록. 목록을 누르면 `/attempts/{id}`.
- 그래프는 SVG 등 이미 있는 것으로 직접 그린다 (차트 라이브러리를 새로 넣지 않는 쪽이 기본, 빌더 판단).
- 필기와 실기는 서로 다른 자격증이라 이력도 따로.
- 결과가 2개 미만이면 그래프 대신 목록만.

## 6. PDF 가져오기 (운영자, 웹 전용)

흐름
1. `POST /api/admin/certificates/{id}/exams/pdf-preview` (multipart: 문제 PDF, 선택: 해설 PDF) → **저장하지 않고** 행 목록을 돌려준다. 행 = CSV 한 줄과 같은 필드 + `warnings`.
2. 화면에서 표로 보여주고 운영자가 고친다. 경고가 있는 행은 "확인 필요"로 표시.
3. "저장"은 행들을 CSV 문자열로 만들어 기존 업로드 API(`POST /api/admin/certificates/{id}/exams`)로 보낸다 → 기존 검증·저장을 그대로 탄다.

변환 (서버, Apache PDFBox)
- 글자를 뽑고, 줄 시작의 `숫자.`로 문제를 자르고, ①②③④ / ❶❷❸❹로 보기를 자른다.
- 과목: `제N과목` 또는 `N과목 :` 줄로 나눈다.
- 정답: 보기 옆 검은 원(❶~❹)이 있으면 그것, 없으면 마지막 장의 정답표 `N.①` 형식.
- 해설 PDF: `<문제 해설>` 뒤 내용을 문제번호로 붙이고 `[해설작성자 : …]`는 뺀다.
- 실패한 문제(보기 4개 아님, 정답 없음 등)는 빼지 말고 경고와 함께 행으로 돌려준다.
- 코드 문제는 줄바꿈이 뭉개진다 → 경고 없이도 운영자가 고칠 수 있게 표에서 여러 줄 편집.

확인한 실제 PDF (로컬에만 있음, 레포에 넣지 않음)
- comcbt 교사용: 보기 옆 ❶~❹ 정답, 99문제 인식
- comcbt 해설집: `<문제 해설> … [해설작성자 : …]`
- 시나공: 2단 편집, 마지막 장 정답표, 코드 줄바꿈 손실
- 세 파일 모두 글자 추출 가능 (스캔 아님)

테스트
- 파서 단위 테스트는 **직접 만든 예시 PDF**(위 두 형식을 흉내 낸 것)로 한다.

## 9. 검토하며 내가 정한 것 (사용자 확인 필요)

- 주관식 CSV는 새 칸을 만들지 않고 `정답번호` 칸에 답 글자를 넣는다 (칸 수를 늘리면 기존 CSV와 헷갈림)
- PDF 저장은 새 저장 API 대신 CSV 문자열로 기존 업로드 API를 재사용한다 (검증 로직 한 곳)
- 연속 공백을 하나로 보는 것은 기본 채점에만 넣는다
