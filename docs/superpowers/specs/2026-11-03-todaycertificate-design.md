# 오늘의 자격증: 설계 문서

작성일: 2026-11-03
상태: 초안 (사용자 승인 전, 리뷰 반영)

## 1. 의도

- **무엇:** 국가자격 필기 기출문제 학습 앱. 한 줄 소개: "시험일까지 매일 오늘 풀 문제를 골라주는 기출 학습 앱".
- **왜:** 취업용 포트폴리오. 사용자는 국내 백엔드(Java/Spring) 직무에 지원하고, 이 프로젝트에서 AI의 도움을 받아 Spring을 공부한다. 사용자는 모든 코드를 면접에서 직접 설명할 수 있어야 한다.
- **기존 상태:** 2022년에 만든 Expo(React Native) + Express + MySQL 앱. Express 서버는 삭제했고, Spring Boot 서버의 뼈대, 로컬 PostgreSQL, 임시 스키마가 `feature/spring-migration` 브랜치에 있다.
- **이 앱만의 특징:** 문제를 쌓아두기만 하는 앱이 아니라, 시험일(D-day), 과목별 과락 위험, 오답을 바탕으로 "오늘 풀 문제"를 골라준다.

## 2. 목표 / 비목표 / 반목표

### 목표
- 사용자는 자격증을 고르고 바로 기출문제를 풀 수 있다. **이것이 핵심 흐름이다.**
- 실제 시험과 같은 시험 모드: 제한시간, 과목별 점수, 과락, 합격 여부.
- 운영자는 화면에서 자격증을 관리하고 회차별 기출문제를 CSV로 올린다.
- 서버, DB, 웹 앱을 배포해서 링크로 접근할 수 있다.

### 비목표 (이번에 만들지 않음)
- 주관식, 실기 문제 (단, 나중에 붙이기 어렵지 않은 구조로 만든다)
- 그림이 있는 문제, 이미지 업로드
- 코드 문법 강조(색칠)
- 공공데이터포털 API 연동
- 글쓰기 커뮤니티 (문제별 댓글, 합격 후기, 게시판)
- 기존의 취득 자격증·후기 기능 (삭제)
- 앱 스토어 배포 (웹 배포만 한다. 코드는 Expo로 유지해서 나중에 앱 빌드는 가능)
- 정교한 복습 간격 알고리즘
- 관리자 가입 화면
- 시험 점수 이력 화면
- UI 개편 (화면은 기능 위주로 단순하게 만든다)

### 반목표 (기술적으로 동작해도 실패로 보는 것)
- 다른 사이트의 문제를 스크래핑해서 넣는 것
- 비밀값(DB 비밀번호, JWT 키 등)이 레포에 들어가는 것
- 사용자가 설명할 수 없는 코드
- 핵심 흐름(자격증 선택 → 기출 풀기)이 완성되지 않은 상태에서 부가 기능을 진행하는 것
- 측정하지 않은 수치나 없는 기능을 README에 쓰는 것

## 3. 제약

- **일정:** 1일차(서버 뼈대, DB) 이후 남은 작업 시간 약 20시간 + 공부 총 6시간. 추정 합계가 약 21시간이라 빠듯하다.
- **서버:** Spring Boot 4.1, Java 25, Spring Data JPA, PostgreSQL 17 (로컬은 Docker Compose).
- **인증:** 비밀번호는 BCrypt로 해시. 관리자 전용 API가 있으므로 요청자 인증이 필수이며 JWT를 쓴다.
- **화면:** 최신 Expo 템플릿으로 클라이언트를 새로 만들고 기존 화면을 옮겨온다 (AI 판단: SDK 46에서 단계별로 올리는 것보다 빠르고, 화면 대부분을 어차피 새로 만든다). 웹으로 빌드한다. SDK 46 웹 확인용으로 설치했던 패키지 변경은 버린다.
- **배포:** 웹은 Vercel (사용자 확인). Vercel은 Spring을 돌릴 수 없으므로 서버는 Render(Docker), DB는 Neon (AI 제안). 계정 생성은 사용자가 직접 한다.
- **데모 공개 방식:** 사용자 쪽은 배포 링크와 README의 일반 회원 데모 계정으로 보여준다 (데모 계정은 AI 판단). 운영자 쪽은 공개하지 않고 데모 영상으로 보여준다 (사용자 결정).
- **문제 데이터:** 실제 기출은 사용자가 직접 모은다. 출처와 공개 범위를 확인해 README에 출처를 적는다. 그전까지 개발과 테스트는 AI가 만든 샘플 문제로 하며 샘플임을 표시한다.
- **스키마 관리:** 개발 중에는 `schema.sql`, 첫 배포 전에 Flyway로 전환한다.
- **레포 규칙:** 브랜치는 `feature/*`, 커밋 메시지는 영어에 `feat:`/`fix:` 등의 접두어, 변경은 PR 단위.
- **기존 API 호환은 필요 없다.** 화면을 새 API에 맞춰 고친다.

## 4. 사용자 기능

### 4.1 회원
- 아이디, 이름, 비밀번호로 가입한다. 가입하면 모두 일반 회원(USER)이다.
- 로그인은 서버에서 처리하고 JWT를 발급한다.

### 4.2 자격증 둘러보기
- **자격증 목록:** 이름, 간단한 설명.
- **자격증 상세:** 설명, 올해 시험 일정(회차별 접수 기간, 시험일), 등록된 기출 회차 목록(예: 2024년 1회). "5개년"은 운영자가 그만큼 올린다는 뜻이며 시스템이 강제하지 않는다.

### 4.3 D-day
- 자격증 상세의 올해 일정에서 응시할 회차를 하나 고른다.
- 홈 화면에 "정보처리기사 필기 D-23"처럼 표시한다.
- 목표는 한 번에 하나다 (AI 판단).

### 4.4 기출 풀기: 회차 선택 후 모드 선택
- **공부 모드**
  - 문제 하나와 보기 4개를 보여준다.
  - 보기를 고르면 바로 정답 여부, 정답, 해설을 보여준다.
  - 문제별 정답률을 보여준다 (4.7).
  - 다음 문제로 넘어간다.
- **시험 모드**
  - 회차 전체를 푼다. 제한시간은 자격증 설정값이고, 남은 시간을 화면에 표시한다.
  - 제출하거나 시간이 다 되면 그때까지 고른 답으로 채점한다. 시간이 끝나면 자동 제출한다.
  - **결과 화면:**
    - 과목별 점수: 과목 정답 수 / 과목 문항 수 × 100
    - 과목별 과락 여부: 자격증의 과락 기준 미만이면 과락
    - 평균 점수
    - 합격 여부: 과락 과목이 없고 평균이 합격 기준 이상이면 합격
    - 문제별 정답 여부, 정답, 해설
- 두 모드 모두에서 문제에 **별표**를 달고 뗄 수 있다.

### 4.5 오답노트
- 두 모드에서 틀린 문제가 자동으로 모인다.
- 나중에 다시 풀어서 맞히면 오답노트에서 빠진다.

### 4.6 별표 문제
- 별표를 단 문제 모음. 여기서 다시 풀 수 있다.

### 4.7 문제별 정답률
- 문제를 푼 뒤 "이 문제 정답률 42%, 가장 많이 고른 오답은 3번"을 보여준다.
- 전체 사용자의 풀이 기록으로 계산한다.

### 4.8 과락 위험 리포트
- D-day로 고른 자격증 기준으로, 내 풀이 기록의 과목별 정답률을 보여준다.
- 정답률이 그 자격증의 과락 기준보다 낮은 과목을 "과락 위험"으로 표시한다.

### 4.9 오늘의 문제 (이 앱의 핵심 특징)
- D-day로 고른 자격증에서 하루 약 20문제를 골라준다.
- 섞는 재료: 다시 풀 때가 된 오답 문제, 과락 위험 과목의 문제, 아직 안 푼 문제.
- 규칙은 단순하게 만든다. 비율과 "다시 풀 때가 됐다"의 기준은 빌더가 정하되, README에서 설명할 수 있어야 한다.

### 4.10 코드가 들어간 문제
- 문제, 보기, 해설 텍스트 안의 코드는 ` ``` `로 감싼다.
- 서버는 텍스트를 줄바꿈과 공백까지 그대로 저장한다.
- 화면은 ` ``` ` 안쪽을 고정폭 글꼴과 회색 박스로 보여준다. 문법 강조는 하지 않는다.

## 5. 운영자 기능

- 회원의 역할은 USER 또는 ADMIN이다. ADMIN은 DB에서 직접 지정한다.
- 자격증 둘러보기를 포함한 모든 기능은 로그인 후에 쓴다 (AI 판단: 인증 규칙을 단순하게 유지).
- 운영자 화면은 같은 웹 앱 안에 있고, ADMIN에게만 보인다 (AI 판단).

### 5.1 자격증 관리
- 자격증 추가와 수정: 이름, 간단한 설명.
- 시험 설정: 제한시간(분), 과락 기준 점수, 합격 평균 기준 점수.
- 과목 목록: 과목 번호와 과목 이름 (예: 1과목 소프트웨어 설계).
- 올해 시험 일정: 회차, 접수 시작일, 접수 마감일, 시험일.

### 5.2 기출 회차 업로드
1. 자격증을 고른다.
2. 회차를 입력한다 (연도, 회차. 예: 2025년 2회).
3. CSV를 올린다. 결과로 "80문제 등록 완료" 또는 오류 목록을 보여준다.

**CSV 형식:** 한 줄이 문제 하나, 첫 줄은 헤더.
`과목번호, 문제번호, 문제, 보기1, 보기2, 보기3, 보기4, 정답번호, 해설`
- 여러 줄짜리 칸(코드)은 CSV 표준대로 큰따옴표로 감싼다.

**검증 (하나라도 실패하면 파일 전체를 저장하지 않는다):**
- 필수 칸이 비어 있지 않은가 (해설은 선택)
- 과목번호가 그 자격증에 등록된 과목인가
- 정답번호가 1~4인가
- 파일 안에서 문제번호가 중복되지 않는가
- ` ``` `가 짝을 이루는가
- 오류는 줄 번호와 이유를 함께 모두 보여준다.

**같은 회차를 다시 올리면** 문제번호 기준으로 덮어쓴다 (AI 판단). 같은 번호의 문제는 내용을 갱신하므로 풀이 기록, 별표, 오답이 유지된다. 새 파일에 없는 문제번호는 관련 기록과 함께 삭제한다. 통째로 지우고 다시 만들면 모든 사용자의 학습 기록이 사라지기 때문이다.

## 6. 데이터 (개략)

빌더가 다듬되, 아래 관계는 지킨다.

- **certificate:** 이름, 설명, 제한시간, 과락 기준, 합격 기준
- **subject:** 자격증에 속함. 과목 번호, 이름
- **exam_schedule:** 자격증에 속함. 연도, 회차, 접수 기간, 시험일
- **exam (기출 회차):** 자격증에 속함. 연도, 회차
- **question:** 회차와 과목에 속함. 문제번호, 문제, 보기 1~4, 정답번호, 해설
- **member:** 아이디, 이름, 비밀번호 해시, 역할, D-day 목표 일정
- **풀이 기록:** 회원, 문제, 고른 보기, 정답 여부, 모드, 시각. 오답노트, 정답률, 과락 리포트, 오늘의 문제가 모두 이 데이터를 쓴다.
- **별표:** 회원, 문제 (중복 없음)
- **시험 응시:** 시험 모드의 시작 시각, 제출 여부, 결과

현재 `schema.sql`, 엔티티, 샘플 데이터는 임시이며, 배포된 DB가 없으므로 자유롭게 다시 만든다. 기존 `member`의 취득 자격증·후기 컬럼은 삭제한다.

## 7. 화면 목록

- **사용자:** 로그인, 회원가입, 홈(D-day, 오늘의 문제 시작, 과락 리포트 요약), 자격증 목록, 자격증 상세, 모드 선택, 공부 모드 풀이, 시험 모드 풀이(타이머), 시험 결과, 오답노트, 별표 문제, 내 학습(과락 리포트 전체)
- **운영자:** 자격증 목록과 편집(과목, 일정, 기준 포함), 회차 업로드와 결과

## 8. 우선순위 (AI 제안, 일정이 밀리면 아래부터 자른다)

5번 안에서는 오늘의 문제 → D-day → 과락 리포트 → 정답률 순서로 만든다. 오늘의 문제가 이 앱의 특징이기 때문이다.

1. 인증, 자격증·과목 관리, CSV 업로드, 자격증 목록·상세, 공부 모드 → 핵심 흐름
2. 시험 모드와 채점
3. 오답노트, 별표
4. 배포 (서버, DB, 웹), README
5. 문제별 정답률, D-day, 과락 리포트, 오늘의 문제
